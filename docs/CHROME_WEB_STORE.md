# Архив подготовки PageVault к Chrome Web Store

28 октября 2026 года выбран выпуск только через [GitHub Releases](https://github.com/akarazhev/pagevault/releases), без регистрации и взноса магазина. Расширение устанавливается вручную; актуальная последовательность находится в [INSTALLATION.md](INSTALLATION.md). Ниже сохранены прежние материалы подготовки на случай отдельного решения о магазине в будущем.

## Артефакты

```bash
go run ./cmd/release --extension-only
```

Загружать в Developer Dashboard следует `dist/PageVault-Extension-1.3.0.zip`, где `manifest.json` находится в корне. ZIP содержит файлы расширения и MIT LICENSE. Полный `PageVault-1.3.0.zip` и PKG не являются пакетом для загрузки в магазин. Формат ZIP описан в [официальной инструкции подготовки](https://developer.chrome.com/docs/webstore/prepare).

Нативный компонент распространяется через [GitHub Releases](https://github.com/akarazhev/pagevault/releases). Текущий macOS PKG явно помечен `-unsigned.pkg`; подпись Developer ID и нотарификация являются отдельным вариантом дальнейшего распространения. Детали: [INSTALLATION.md](INSTALLATION.md).

## Текст карточки

**Название:** PageVault — локальный архив.

**Краткое описание:** Сохраняйте просматриваемые страницы в структурированном JSON в локальную SQLite.

**Подробное описание:**

PageVault сохраняет загруженное содержимое выбранных вами веб-страниц в личный архив на компьютере. Включите запись для сайта, затем читайте, прокручивайте и раскрывайте обсуждения как обычно. Новое содержимое дополняет архив.

- Текст, заголовки, таблицы, списки и код в структурированном виде.
- История сохранённых состояний и накопленные замеченные блоки.
- Поиск по тексту и сайту, просмотр и экспорт JSON.
- Устойчивая очередь доставки в локальную SQLite.
- Локальный MCP для чтения архива через выбранный вами агент, включая Codex и Claude Code.

Для SQLite требуется отдельно установить локальный компонент PageVault. Расширение показывает шаги подключения и фактический путь базы. Данные не загружаются на сервер разработчиков; если вы подключаете облачную модель через своего агента, сведения могут передаваться её провайдеру. Не загруженное содержимое сайта, закрытые области DOM, изображения/canvas и медиафайлы могут не попасть в архив.

Основной язык — русский; категорию в Dashboard выберите по назначению личного архива/продуктивности. Не добавляйте обещания полного офлайн-воспроизведения сайтов, автоматической установки системной программы или полностью локальной работы облачной модели.

## Разрешения и обработка данных

| Разрешение | Назначение |
|---|---|
| `activeTab` | Ручное сохранение открытой пользователем страницы |
| `scripting` | Запуск парсера DOM в разрешённых вкладках |
| `storage` | Параметры записи, список сайтов и состояние доставки |
| `alarms` | Повторная доставка принятых снимков после остановки service worker |
| `nativeMessaging` | Связь с локальным помощником SQLite |
| `unlimitedStorage` | Локальная очередь снимков в пределах собственных лимитов PageVault |
| Опциональные `http://*/*` и `https://*/*` | Пользователь включает доступ отдельно для нужных сайтов |

Политика для поля Privacy policy URL после публикации документа:

`https://github.com/akarazhev/pagevault/blob/main/docs/PRIVACY.md`

В сведениях Dashboard нужно раскрыть обработку содержимого сайтов, URL и потенциальных личных/пользовательских данных страниц. Отсутствие собственного облачного сервера не отменяет раскрытия локальной обработки. Сведения в карточке и формах должны соответствовать [PRIVACY.md](PRIVACY.md) и фактическим функциям; правила раскрытия описаны у [Chrome Web Store](https://developer.chrome.com/docs/webstore/program-policies/user-data-faq).

## Изображения

Иконка 128×128 находится в `extension/icons/icon128.png`. Подготовьте скриншоты настоящего архива, настроек подключения и шагов установки, используя только искусственные страницы. Команда `node scripts/store-screenshots.cjs` создаёт PNG 1280×800 в `dist/store-assets/`; требуется установленный Playwright/Chromium.

Для карточки требуется иконка и хотя бы один скриншот. Размеры и необязательные материалы приведены в [требованиях Dashboard](https://developer.chrome.com/docs/webstore/cws-dashboard-listing). Перед загрузкой проверьте изображения вручную; личные профили и пользовательские страницы для них не используются.

## Инструкция для проверки

1. Установить доступный нативный компонент и выбрать Chrome. Убедиться, что его регистрация разрешает ID проверяемого расширения.
2. Установить расширение и открыть его настройки. Нажать «Проверить подключение»; должны появиться версия и путь SQLite.
3. Открыть общедоступную тестовую страницу без входа в аккаунт, включить запись сайта и вручную сохранить снимок.
4. Найти страницу в архиве, проверить текст/таблицы/код, историю и экспорт JSON.
5. Отключить запись сайта и проверить сохранность предыдущих данных. Удалить тестовую страницу в архиве.
6. При необходимости подключить локальный MCP-клиент по [MCP.md](MCP.md); учётные записи агента не требуются для основных функций браузерного архива.

Предоставьте проверяющему ссылку на установщик, поддерживаемые ОС, описание отдельной установки и тестовую страницу. Не передавайте реальные архивы или личные учётные данные.

## Перед отправкой

- Настроить аккаунт разработчика и контакты поддержки; данные аккаунта и регистрационные действия выполняет владелец.
- Получить окончательный ID магазина. Проверить `manifest.key`, `docs/extension-id.txt`, `internal/buildinfo` и native `allowed_origins`; при смене ключа пересобрать расширение и программы.
- Предоставить реальные загрузки компонента и точные инструкции, учитывающие подпись или её отсутствие. Проверить Windows/Linux комплект на соответствующих ОС.
- Проверить URL политики, описание данных, изображения и инструкции после публикации файлов.
- Загрузить extension ZIP и отправить на проверку по [процедуре публикации](https://developer.chrome.com/docs/webstore/publish).

Этот этап подготавливает материалы; он не меняет видимость проекта, не регистрирует аккаунт и не отправляет расширение в магазин.
