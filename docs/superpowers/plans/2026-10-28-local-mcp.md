# Local MCP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a local agent read PageVault through MCP and record the agreed distribution model.

**Architecture:** Existing executable gains a stdio MCP command backed by a genuinely read-only SQLite connection. Share archive query behavior; keep Native Messaging unchanged.

**Tech Stack:** Go 1.27.3, official MCP Go SDK v1.8.0, modernc SQLite, existing Node.js 26.12.1/Playwright tests.

**Spec:** docs/superpowers/specs/2026-10-28-local-mcp-design.md

## Global Constraints

- Existing schema 1 only; read-only mode never creates or initializes an archive.
- Local stdio only, no arbitrary SQL/write tools and no application network listener.
- Lists default 20/max 100; JSON chunks default 8,000/max 16,000 code points; tool data bounded to 32 KiB.
- Preserve exact numeric tokens, source provenance, block structure and warnings; omit stored HTML in MCP snapshot documents.
- Keep Native Messaging, extension ID, and browser behavior compatible; release version 1.2.0.
- Record CWS/installer/updater as planned work, not implemented features.

## Review Focus

- SQLite URI punctuation must not override read-only flags: test literal filenames and failed writes after query_only is disabled.
- Live browser commits must remain visible: test concurrent writer/read-only reader.
- A changing accumulated document must not mix chunks: require and test document hashes on continuation.
- Unicode and oversized fields must fit response bounds: exercise chunk reassembly and bounded summaries.
- Stdio output must stay protocol-clean and terminate: test a real compiled command with an SDK client and missing-db errors.
