# Архитектура PageVault

## Компоненты

| Компонент | Ответственность |
|---|---|
| `extension/extractor.js` | Синхронный разбор DOM в упорядоченные блоки; границы объёма и предупреждения |
| `extension/adapters/` | Дополнительные метаданные сайтов; общий парсер остаётся основой |
| `extension/content.js` | Наблюдение за DOM и доступными корнями, задержка изменений, SPA-навигация и снимки |
| `extension/background.js` | Разрешения сайтов, проверка источника сообщений, настройка скриптов, Native Messaging |
| `extension/lib/native-client.js` | Постоянный native-порт, сопоставление ответов, обработка разрыва и сроков чтения |
| `extension/lib/outbox.js` | Устойчивая очередь IndexedDB с версией записи и лимитами |
| `extension/lib/delivery.js` | Повторная доставка; удаление из очереди после подтверждения SQLite |
| `extension/ui/` | Меню, настройки, поиск, версии и просмотр накопленного архива |
| `cmd/pagevault/` | CLI, конфигурация установленной программы и вход в native-режим |
| `internal/native/` | Протокол stdio и команды; большие ответы читаются частями |
| `internal/archive/` | SQLite, транзакции, уникальные снимки, накопленные блоки и поиск |
| `internal/install/` | Пользовательская регистрация прямого исполняемого файла для каждого браузера |
| `cmd/release/`, `internal/release/` | Сборка Go-программ для шести платформ и чистого ZIP |

## Поток данных

Content script получает настройки расширения и работает только на включённом origin либо по ручному запросу. Парсер собирает доступные блоки страницы. Фоновый модуль проверяет источник, записывает снимок в IndexedDB и возвращает подтверждение постановки в очередь.

Доставка передаёт снимок локальному процессу через Native Messaging. Помощник проверяет схему, выполняет транзакцию и подтверждает запись. Только после этого расширение удаляет соответствующую версию записи из очереди. Если похожий снимок был обновлён, пока шла отправка, старое подтверждение не удалит новый экземпляр.

При остановке service worker данные очереди остаются в IndexedDB. Повторная доставка запускается при новом событии, старте браузера, периодическом сигнале и вручную. SQL-дедупликация делает повторную доставку безопасной для истории версий.

## SQLite

`pages` хранит идентичность страницы по точному URL и служебные даты. `captures` хранит уникальные состояния в исходном JSON. `blocks` хранит уникальные блоки каждой страницы с порядком первого появления. Идентификатор блока рассчитывается по его структурированному содержимому, поэтому изменённый блок остаётся отдельной записью.

Используются внешние ключи, транзакции, WAL и ожидание блокировок. Повторная установка помощника не удаляет базу. Код и настройки нативного запуска находятся вне папки распакованного расширения.

`archive.Open` вызывается один раз перед native-циклом. `database/sql` ограничен одним открытым и одним свободным соединением: `SetMaxOpenConns(1)`, `SetMaxIdleConns(1)`, без ограничения времени жизни или простоя. Поэтому запросы переиспользуют физическое соединение. Все результаты `Rows` закрываются до следующего запроса, которому нужно это соединение. Соединение закрывается при завершении процесса.

Для хэширования используется детерминированная сериализация стандартной библиотекой Go `encoding/json`: ключи объектов упорядочены, числа декодируются через `json.Number`, чтобы не терять точность. Временные поля и HTML исключены из семантического хэша снимка. Специального воспроизведения форматирования Python нет. `captured_at` использует RFC3339 с часовым поясом, как `Date.toISOString()` браузера.

Трёх таблиц достаточно для текущего сценария. ORM, фоновый сервер, миграционный фреймворк и отдельная поисковая система не добавляются. Неподдерживаемый ненулевой `PRAGMA user_version` отклоняется вместо молчаливой перезаписи версии.

`pages.list`/`pages.get` возвращают ограниченные по размеру представления заголовков и других полей. Полные исходные значения доступны через chunked JSON. Если адрес слишком длинный для краткого ответа, он не превращается в усечённую кликабельную ссылку.

## Почему Native Messaging

Браузер запускает локальный процесс по необходимости; постоянно работающий HTTP-сервер для архива не требуется. Манифест помощника разрешает обращения только от установленного ID расширения. Публичный ключ расширения закрепляет ID при загрузке из разных папок.

Постоянный `connectNative` заменяет старый `sendNativeMessage`, который запускал процесс для каждого обращения. При открытом порте один процесс обрабатывает последовательность кадров. После аварии новый процесс появляется при следующем запросе. Срок ожидания отдельного чтения не закрывает общий порт и не освобождает выполняющуюся мутацию.

Установщик копирует Go-программу в `<runtime>/<browser>/pagevault-host[.exe]`, записывает рядом `pagevault.json` и регистрирует этот исполняемый файл напрямую. Драйвер `modernc.org/sqlite` включён в программу; внешняя библиотека SQLite, Python или интерпретатор команд для native-режима не нужны. В Windows регистрация выполняется в HKCU.

Обычные веб-страницы не могут вызывать команды управления архивом через интерфейс расширения. Фоновый модуль различает сообщения content script и страниц самого расширения. Сохранённые HTML и JavaScript обрабатываются как данные.

## Расширение возможностей

Дополнительные семантические поля вводятся адаптерами. Для нового вида блока нужно добавить извлечение, безопасное отображение и регрессионную фикстуру. Формат JSON версионируется полем `schema_version`; несовместимая схема должна получать новую версию и миграцию.

Firefox потребует отдельного манифеста/интеграции разрешений и регистрации Native Messaging. Сбор сетевых ответов через DevTools, OCR и загрузка медиа — самостоятельные дополнительные модули, не необходимые для основной цепочки DOM → JSON → SQLite.
